## 1. 로그인

| 단계 | 항목 | 세부 내용 |
|---|---|---|
| 1-1 | 이메일 입력 | `아이디 입력` 칸 + 도메인 선택(드롭다운, 기본값 `naver.com`) 조합으로 이메일 완성 |
| 1-2 | 비밀번호 입력 | 비밀번호 표시/숨김 토글 버튼 제공 |
| 1-3 | [로그인] 선택 | `POST /api/auth/login` 호출 |

**성공 시**
- 토스트: `로그인 성공 · 홈 대시보드로 이동합니다`
- 홈 대시보드로 이동

**실패 시 (Tooltip)**
| 상황 | 메시지 |
|---|---|
| 이메일/비밀번호 불일치 | `이메일 또는 비밀번호가 일치하지 않습니다.` (API 401 응답 그대로 노출) |

**하위 링크**
- `회원가입` → 회원가입 화면 이동
- `비밀번호 찾기` → 4단계 플로우: 이메일 인증 → 인증번호 확인 → 새 비밀번호 설정 → 완료 (`POST /api/auth/password/code` → `/password/verify` → `/password/reset`)

## 2. 회원가입

> 아바타/프로필 사진 업로드는 회원가입 화면에 **없음**. 프로필 사진은 가입 후 "내 정보"에서 별도로 등록한다.

| 단계 | 항목 | 세부 내용 |
|---|---|---|
| 2-1 | 이름 입력 | 필수, 최대 15자, 한글·영문·숫자 외 문자는 입력 중 자동 필터링 |
| 2-2 | 이메일 입력 | 아이디 입력 칸 + 도메인 선택(드롭다운, 기본값 `naver.com`, `직접입력` 가능) 조합. 필수, 아이디는 영문/숫자만·최대 15자, 전체 이메일 최대 30자 |
| 2-3 | 비밀번호 입력 | 표시/숨김 토글, 비밀번호 확인 입력 별도. 필수, **4~16자**, 영문·숫자·특수문자만(한글 입력 시 자동 필터링) |
| 2-4 | [가입하기] 선택 | `POST /api/auth/signup` (JSON: `name`, `email`, `password`) 호출 → 성공 시 자동 로그인 → `/signup/complete` 이동 |

이메일 중복 확인은 별도 단계 없이, 가입 버튼 클릭 시 서버가 `409`로 응답하면 그 자리에서 안내한다.

**Tooltip / 에러 메시지**
| 상황 | 메시지 |
|---|---|
| 이름 누락 | `이름을 입력해 주세요.` |
| 이메일 아이디 형식 오류 | `올바른 아이디 형식을 입력해 주세요.` |
| 이메일 도메인 오류 | `이메일 도메인을 입력해 주세요.` / `올바른 도메인 형식을 입력해 주세요. (예: example.com)` |
| 비밀번호 4자 미만 | `비밀번호는 최소 4자 이상 입력해야 합니다.` |
| 비밀번호 16자 초과 | `비밀번호는 최대 16자까지 입력할 수 있습니다.` |
| 비밀번호 허용 문자 외 입력 | `비밀번호는 영문, 숫자, 특수문자만 입력할 수 있습니다.` |
| 비밀번호 확인 불일치 | `비밀번호가 일치하지 않습니다.` |
| 이메일 중복 (409) | `중복된 이메일이 존재합니다. 다시 입력해주세요.` |
| 기타 서버 오류 | `회원가입 처리 중 오류가 발생했습니다.` |

**성공 시**
- 회원가입 후 자동 로그인 → `/signup/complete` 이동

## 3. 보유 예금 등록

두 가지 입력 경로 제공: **① 앱 화면 캡처로 자동 등록(OCR)**, **② 직접 입력**

### 3-1. 공통 안내

| 위치 | 문구 |
|---|---|
| 상단 안내 배너 | `현재 KB국민은행 예금 상품만 등록할 수 있어요 · 계좌번호는 숫자 14자리로 입력해주세요` |

> 배너 문구(14자리)와 실제 계좌번호 검증(14자리 고정, `DepositRequestDTO.java`) 일치 확인됨. 기존에 "API 검증은 10~16자리"라고 적었던 건 예전 API명세서.md를 그대로 옮긴 것이었고, 코드 확인 결과 오류였음.

### 3-2. OCR 자동 등록

| 단계 | 항목 | 세부 내용 |
|---|---|---|
| 3-2-1 | [앱 화면 캡처로 자동 등록] 선택 | 은행 앱 캡처 이미지 업로드 |
| 3-2-2 | 이미지 업로드 | `POST /api/ocr/extract` (multipart) 호출, 비로그인 상태에서도 호출 가능 |
| 3-2-3 | 추출 중 | 로딩 화면 표시: `추출 중입니다... 캡처에서 예금 정보를 읽고 있어요 · 보통 5~6초 정도 걸려요` |
| 3-2-4 | 추출 완료 | 상단 배지: `OCR 추출 완료`, 인식된 값은 **노란 배경**으로 표시되어 폼에 자동 채워짐 |
| 3-2-5 | 인식 실패 항목 | 인식하지 못한 칸은 비워 두고 사용자가 직접 입력 |
| 3-2-6 | [확인했어요 · 등록하기] 선택 | `POST /api/deposits` 호출 |

**Tooltip / 에러 메시지**
| 상황 | 메시지 |
|---|---|
| OCR 파일 오류 | `INVALID_OCR_FILE` → 화면 노출 문구 `[확인 필요]` |
| Gemini 응답 지연 | `이미지 분석 시간이 초과되었습니다.` (`OCR_TIMEOUT`) |
| Gemini 호출/응답 실패 | `OCR_PROVIDER_ERROR` / `OCR_RESPONSE_ERROR` → 화면 노출 문구 `[확인 필요]` |
| 캡처가 없을 때 | 사용자가 처음부터 직접 입력하도록 안내 |

### 3-3. 직접 입력

| 단계 | 항목 | 필수 여부 | 검증 규칙 |
|---|---|---|---|
| 3-3-1 | 예금 종류 | O | 정기예금 고정 |
| 3-3-2 | 은행명 | O | 30자 이내, 한글/영문/공백만 (백엔드 기준) — 화면 입력창은 12자에서 자동으로 잘림 |
| 3-3-3 | 상품명 | O | 50자 이내, 한글·영문·숫자·괄호·하이픈·마침표·공백, 한글 또는 영문 최소 1자 포함 (백엔드 기준) — 화면 입력창은 25자에서 자동으로 잘림 |
| 3-3-4 | 계좌번호 | O | 숫자 **14자리 고정** |
| 3-3-5 | 가입일 / 만기일 | O | 전송값 `yyyyMMdd` 8자리(화면 표시는 `YYYY-MM-DD`), 만기일 > 가입일. 화면 전용 추가 규칙: 가입일 ≤ 오늘, 만기일 > 오늘(백엔드는 검증 안 함) |
| 3-3-6 | 가입 금액 | O | 1만원 이상 100억원 이하 |
| 3-3-7 | 기본 금리 | O | 0~20%, 소수점 둘째 자리까지 |
| 3-3-8 | 적용금리(우대금리 포함) | O | 0~20%, 소수점 둘째 자리까지, 적용금리 ≥ 기본금리 |
| 3-3-9 | [필수 항목을 입력해주세요] 버튼 | - | 필수값 미충족 시 버튼 비활성 문구로 표시 |

> 은행명·상품명은 화면 입력창이 백엔드 제한(30자/50자)보다 짧게(12자/25자) 잘라내므로, 실제 화면에서는 `INVALID_LENGTH`(글자수 초과) 에러가 발생하지 않는다. 직접 API를 호출할 때만 재현 가능.

**Tooltip / 에러 메시지 (errorCode 매핑, `DepositRequestDTO.java` 기준)**
| errorCode | 상황 | 메시지 예시 |
|---|---|---|
| `REQUIRED_FIELD` | 필수값 누락 | `은행명을 입력해주세요` 등 필드별 문구 |
| `INVALID_ACCOUNT_NUMBER` | 계좌번호 형식 오류 | `KB 계좌번호는 숫자 14자리로 입력해주세요` |
| `INVALID_LENGTH` | 글자수 초과 | `은행명은 30자 이내로 입력해주세요` / `상품명은 50자 이내로 입력해주세요` |
| `INVALID_CHARACTER` | 허용되지 않은 문자 | `은행명은 한글과 영문만 입력할 수 있습니다` / `상품명에 사용할 수 없는 문자가 있습니다` / `상품명에 한글 또는 영문이 포함되어야 합니다` |
| `INVALID_AMOUNT` | 금액 범위 오류 | `가입금액은 1만원 이상 입력해주세요` / `가입금액은 100억원 이하로 입력해주세요` |
| `INVALID_RATE` | 금리 범위/대소/소수점 오류 | `기본금리는 0~20% 사이로 입력해주세요` / `소수점 둘째 자리까지 입력해주세요` / `적용금리는 기본금리보다 크거나 같아야 합니다` |
| `INVALID_DATE` | 만기일 ≤ 가입일 | `만기일이 가입일보다 빠릅니다` |
| `INVALID_FORMAT` | 숫자 칸에 비숫자 입력 (JSON 파싱 단계, `validate()` 이전) | `입력값이 올바르지 않습니다. 금액과 금리를 다시 확인해주세요.` — 화면은 입력 시 숫자만 남기므로 사실상 도달 어려움 |

**성공 시**
- 토스트/응답: `등록 완료`

## 4. 보유 예금 수정 · 삭제

| 단계 | 항목 | 세부 내용 |

## 5. 득실 비교 - 조건 입력

| 단계 | 항목 | 세부 내용 |
|---|---|---|
| 5-1 | 필요한 금액 입력 | 직접 입력 또는 `+100만` `+500만` `초기화` 버튼 |
| 5-2 | 비교에 사용할 보유 예금 선택 | `GET /api/deposits/list` 목록 중 1건 선택. 만기 지난 예금은 회색 처리되어 선택 대상에서 제외 |
| 5-3 | 신용점수(KCB) 확인 | `내 정보`에 저장된 값 표시, 안내: `등급별 금리는 KB국민은행 실제 심사금리가 아닙니다. 동일 은행 일반신용대출의 신용점수 구간별 평균 비율 기반 추정값입니다.` |
| 5-4 | 월 상환 가능 금액 확인 | `내 정보`에 저장된 값 표시 |
| 5-5 | 대출 종류 선택 | `전세대출` / `신용대출` 중 1개 |
| 5-6 | [손익 비교하기] 선택 | 다음 단계(자격 확인)로 이동 |

### 5-A. 자격 확인

> 자격 질문은 **대출 종류마다 다르므로** 화면에 개별 질문을 고정 나열하지 않는다. 신용대출은 프론트에 고정된 질문 3개(건강보험 직장가입 여부 · 6개월 이상 근무 여부 · STAR CLUB 베스트 등급 이상 여부)를 쓰고, 전세대출은 `GET /jeonse-loans/eligibility-questions` 응답을 그대로 렌더링하므로 대출 상품마다 질문 구성이 달라질 수 있다.

| 단계 | 항목 | 세부 내용 |
|---|---|---|
| 5-A-1 | 자격요건 질문 응답 | 신용대출: 고정 질문 3개 / 전세대출: API 응답 기반 (대출 상품별로 다름) |
| 5-A-2 | 손익비교 조건 질문 응답 | 분할 인출 가능 여부 · 만기 시 대출 상환 예정 여부 — 신용·전세 공통 문구, 같은 화면 내 별도 그룹으로 표시 |

**공통 안내 배너** (그룹별로 반복 노출): `잘 모르시겠다면 우선 '예'를 선택해 주세요.`

### 5-B. 우대금리 확인

| 단계 | 항목 | 세부 내용 |
|---|---|---|
| 5-B-1 | 우대금리 항목별 응답 | `POST /api/credit-loans/preferential-rate`(신용) / `POST /jeonse-loans/preferential-rate`(전세)에 사용할 `preferentialQuestionIds` 구성 |
| 5-B-2 | 단일 선택형 항목(예: KB신용카드 이용실적) | 라디오 버튼 — 조건 미충족 시 `해당 없음` 선택 |

**공통 안내 배너**: `잘 모르시겠다면 우선 '해당없음 또는 아니요'를 선택해 주세요.`

## 6. 득실 비교 - 결과 확인

| 단계 | 항목 | 세부 내용 |
|---|---|---|
| 6-1 | 계산 요청 | `POST /api/comparisons` 호출 |
| 6-2 | 결과 표시 | 헤드라인: `{예금명} 중도해지 {savingAmount}원 더 이득` (또는 대출 쪽이 유리할 때는 반대 문구) |
| 6-3 | 옵션 비교 카드 | `① 중도 또는 부분해지` / `② 신용대출·예금 유지` 나란히 표시, 유리한 쪽에 `추천` 배지 |
| 6-4 | 손실 비교 막대 그래프 | 신용대출 비용 vs 중도해지 비용 |
| 6-5 | 월 예상 상환액 표시 | 입력값 그대로 표시 |
| 6-6 | 하단 안내 문구 | `본 결과는 [득실]만의 계산기로 산출한 참고용 예상값이며, 실제 적용 금리와 대출한도는 개인의 신용조건 및 금융기관 심사 결과에 따라 달라질 수 있습니다.` |
| 6-7 | [예금 중도해지로 진행] / [대출로 진행] | 클릭해도 **화면 이동 없이 확인 모달만 표시**. `대출` 라벨은 신용대출/전세자금대출로 동적 표시되며 대출 종류 구분 없이 동일하게 처리 |

**클릭 시 모달 흐름**
- 손해 보는 쪽을 선택하면 먼저 손실 경고 모달: `{손해금액}원 손해를 보는 선택입니다. 진행하시겠습니까?`
- 확인 후 완료 모달: `{대출/예금 중도해지}(으)로 진행합니다.`
- 실제 신청 처리·화면 이동 로직은 아직 미구현 (코드 내 TODO 주석 존재)

**계산 불가 시 (`feasible: false`)**
| reason | 노출 문구 |
|---|---|
| `PAYMENT_TOO_LOW` | 월 상환 가능 금액 부족 안내 `[확인 필요]` |
| `EXCEED_LOAN_LIMIT` | 대출 한도 초과 안내 `[확인 필요]` |

> 이 경우 이력(comparisons)에는 저장되지 않습니다.

## 7. 내 정보 수정 · 로그아웃 · 회원탈퇴

| 단계 | 항목 | 세부 내용 |
|---|---|---|
| 7-1 | 이름/이메일 수정 | `PUT /api/users/me` (multipart) |
| 7-2 | 신용점수 수정 | `PATCH /api/users/me/credit-score` — 안내: `KCB에서 직접 조회 후 입력합니다` |
| 7-3 | 월 상환 가능 금액 수정 | `PATCH /api/users/me/max-monthly-payment` — 안내: `매월 부담할 수 있는 최대 상환 금액입니다.` |
| 7-4 | [로그아웃] 선택 | 확인 모달: `정말 로그아웃 하시겠습니까?` → [취소] / [로그아웃] |
| 7-5 | [회원탈퇴] 선택 | 확인 모달: `정말로 탈퇴하시겠습니까?` → [취소] / [탈퇴] |

- 물리 삭제가 아닌 **이메일 익명화** 방식 (UNIQUE 제약 회피 + 비교 이력 보존 목적) `[확인 필요: 사용자 화면에 노출되는 안내 문구]`
